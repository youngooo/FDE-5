# 第五周作业 · 青禾会员运营助手

[下载作业提交包](./w05-submit.zip?raw=true)。解压后，先打开 `artifacts/w05/mvp_v1_report.json`，其中 `verification_cases` 按 A～E 五组列出预期、实际结果和证据文件路径。

本作业使用课程提供的合成数据，接续 W04 的 CRM 清洗结果。程序依据迁移和账户核查记录关联旧 POS 与新 CRM 账户，按统一会员归集订单，再供门店直接查询和运营 Agent 圈选会员。运营建议用于业务复核，实际联系由业务人员另行确认。

## 从一笔订单核对圈选结果

B 组按来源账户的注册门店筛选会员。参考日为 2026-09-01，条件为近 12 个月净消费至少 3,000 元、距最近有效购买满 60 天，渠道为短信。

在门店 `1203` 的归档运行中，两个入口均返回 1 名候选。该会员的 CRM 净消费为 4,432.36 元，旧 POS 净消费为 305.20 元，合计 4,737.56 元。其中 305.20 元发生在门店 `2707`，仍计入该会员的窗口消费。这里的两个口径分别回答“会员注册在哪家店”和“该会员在所有已覆盖门店消费了多少”。最近一笔有效订单为 `CRM:O20260625000129`，日期为 2026-06-25，距参考日 68 天。门店 `1004` 在相同条件下返回空名单。

可对照包内的 `evidence/step-5/direct-1203.json` 和 `evidence/step-5/agent-20261121-002816/B-1203.json` 核查两个入口。B 组报告另记录了一项使用体验问题：追问具体订单时，Agent 曾列出整页 31 笔流水，仍需验证能否优先呈现目标订单及依据。

## 验证与复核

A 组验证同一会话从指标查询切换到会员详情。B 组对照两家门店的圈选和建议。C 组覆盖明确禁联与渠道待核。D 组检查修改客户规则后查询结果是否随之变化。E 组验证 59／60／61 天边界、退款及取消订单、购买人数口径和更换筛选条件后的名单集合。

包内 `artifacts/w05/precheck.json` 记录了 20 项公开自检全部通过。自检覆盖结构、版本、映射一致性和金额守恒等项目；业务解释可结合原始输出人工复核，全公司精确自然人数仍待补证。

复跑需配合课程发放的 W05 工程、对应版本数据和 W04 输入，使用包内客户实现与请求参数，依次执行 `prepare`、`bind`、`init`，再通过直接入口和运营 Agent 运行报告中的用例。
